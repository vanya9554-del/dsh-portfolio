2The x402 handshake, end to end

x402 turns HTTP back into its 1996 meaning: 402 Payment Required is a price quote, not an error. An agent probes, signs a USDC authorisation, retries with proof, and gets the payload.

Our seller returns an accepts[] array describing price, asset, network and recipient. The facilitator verifies the EIP-3009 authorisation and settles it on Base; only then does the worker produce the payload and attach the settlement receipt.

GET /.well-known/x402            → service manifest (indexes read this)
GET /openapi.json                → routes with x-payment-info
GET /check?name=x                → 402 + accepts[]  (50 000 µUSDC)
GET /data/termix-open-orders     → 402 + accepts[]  (100 000 µUSDC)

4Three things that almost stopped it

  • Ephemeral tunnels are rejected. A trycloudflare URL gets refused by reviewers — and by our own catalogue submission — because it will be gone tomorrow. A named Workers domain fixed it.
  • Facilitator dialects differ. The public x402.org facilitator serves testnets only; a production Rail on Base mainnet means a different facilitator and a payload schema that is close to, but not identical with, the spec. Settlement compatibility has to be tested, not assumed.
  • “Building it” is 10% of the job. The catalogue review queue, directory manifests, pricing against an existing $0.10 competitor — that is where the hours go.
Economics of this channel: each call costs us ~0 (edge worker, no storage), and pays $0.05–$0.10. Break-even against a month of compute needs a few hundred calls — plausible only with catalogue distribution. That is why the next release is a job-alert feed rather than another checker: alerts are looked at daily, checks are not.
